# DSH 设备同步

在多个 DSH profile 之间同步第三方插件的版本/启停状态、明确选择的插件配置字段和记忆文件。支持一个中心管理多个设备，或两台设备点对点交换。远端提供候选状态，本机策略和审批决定是否写入。

当前版本：**0.2.0**。已核验的宿主版本：**DSH 0.2.2-rc.3**。运行代码为已提交的 JavaScript，无运行时 npm 依赖、无安装构建脚本。

## 安装与入口

GitHub 仓库根就是可安装包根。在 DSH **插件 → 添加插件** 中填写：

```text
github:coollcat/dsh-plugin-sync
```

CLI 使用同一个来源，把 `<profile>` 换成正在使用的 profile 名称：

```sh
dsh plugin --profile <profile> add github:coollcat/dsh-plugin-sync
```

Web 的 profile 常用 `web`，桌面常用 `desktop`，应以实际实例为准。安装到另一个 profile 不会改变当前页面。安装结果为 `applied` 后刷新页面；若显示 `restart-required`，重启对应 DSH 实例后再刷新。

安装启用后有两个入口：

- **插件 → 设备同步**：配对、提案、差异计划、审批、结果与离线快照。
- **设置 → 设备同步设置**：完整策略与同步面板，策略配置排在前面。

需要固定版本时，把安装来源写成 `github:coollcat/dsh-plugin-sync#<完整提交 SHA>`。更新仍使用同一个仓库来源；替换已加载的宿主代码应按 DSH 给出的重启提示处理。

## 第一次使用

1. 在中心和设备的实际 profile 中安装插件。
2. 打开设置，按需查看本机资源目录，选择纳入范围。配置还必须指定非秘密字段的路径；记忆文件默认不对外导出。
3. 中心选择“建立中心”，再按“生成邀请”。设备输入中心地址和邀请，选择“加入中心”。邀请是一次性配对入口，24 小时过期；请私下传递。
4. 中心“发布纳入同步范围的本机资源”；设备检查插件、配置或记忆差异。
5. 查看计划、处理冲突，勾选操作并批准，再点“应用已批准操作”。结果会区分已应用、需重启、失败、冲突和部分完成。

设备也可提交提案；中心接受后只发布新的期望修订，不会替设备绕过本机批准。详见 [使用说明](docs/USAGE.md)。

## 默认安全边界

- 安装、升级、配置写入、记忆写入和自动应用默认关闭；启用/停用能力可生成手动审批计划。
- 配置与记忆必须明确选入。未知配置 schema 默认不外发，配置还要逐字段设置白名单；键名/值的秘密识别只是额外防线。
- 系统包与同步器自身不可由同步计划修改。本机专属规则优先于其他选择；缺席不会变成卸载或文件删除。
- 批准绑定计划内容、来源修订、本机基线和本机策略。改变其中任一条件，必须重新检查和批准。
- 托管自动应用只覆盖低风险启停与配置字段写入。安装、升级、记忆覆盖、冲突覆盖、离线快照和高风险批次仍需人工批准。
- 非回环地址必须 HTTPS。SSH 使用系统 OpenSSH 的直接 TCP 转发，严格验证 `known_hosts`；凭据经加密通道输入流传递，无远端 shell/curl，也不把 bearer 放进 argv。
- 不同步会话、模型凭据、配对密钥或整个 profile。状态和凭据按 home/profile 隔离。撤销设备会立即停止该设备后续访问。

## 支持范围与限制

同步应用支持精确 registry 版本的安装/升级以及已识别插件的启停。无法复现的本地目录/来源不会伪装成 registry 包；Git/file 来源不会被自动安装。插件本身可通过上面的 GitHub 来源直装，这与同步安装其他插件是两件事。

点对点模式目前是一对设备；监听端可排队提案，由加入端下次检查时领取。多设备使用中心模式，无自动选主、传递信任或全网网状路由。

记忆采用文件级同步：`$DSH_HOME/.dsh-memory`、`$DSH_HOME/persona`、`$DSH_HOME/soul`，只允许已注册文本扩展名，每文件最多 256 KiB。共享目录有逐文件 owner 和写入锁；符号链接路径被拒绝。覆盖前生成备份。

离线快照有完整性校验；有本机可识别的共享密钥时使用 HMAC。未签名快照会明确标记来源不可信。签名不提供加密，共享密钥持有方均能生成有效签名。所有快照只生成计划，不直接写入、不提升同步基线。

本插件不承诺跨包管理器、配置编辑器、文件系统的全局事务，也不承诺撤销第三方插件的外部副作用。收费模型调用、跨两台物理主机的网络连通性和各操作系统组合须按自己的部署环境验证。

## 开发与审计

```sh
npm ci --ignore-scripts
npm run verify
npm pack --dry-run
```

这些步骤只用于开发与发布检查，普通使用者直接通过 DSH 安装即可。开发依赖 React/renderer 只用于界面回归；运行时 React 由 DSH 提供。
