# 使用说明

## 确认安装在正确实例

节点是 DSH profile，而不是整台电脑。在插件管理中确认“设备同步”已安装并启用，再从“插件 → 设备同步”进入面板；左下角“设置”里不再重复放一份。如果只有另一套测试实例中出现入口，当前实例仍需要安装。安装器返回 `applied`、`restart-required`、失败等状态时，按实际结果处理；不要用包目录存在来判断界面已经加载。

Web 和桌面都使用 README 的同一 GitHub 来源。更换 profile 名即可，不需要为桌面另做安装包。此前真实宿主验收基于 Linux 的 DSH 0.2.2-rc.3；0.3.0 在同一宿主范围做单机实测，其他宿主版本按 manifest 的兼容范围检查，并以安装结果为准。

## 面板一览

顶部是设备名、角色（未配对/中心/设备/点对点）、连接状态、刷新，以及暂停/恢复；未配对时不显示暂停。下面按左右两列排（窄屏自动变成单列）：

- **左列 · 先配好**：**建议**（未纳入的插件一键纳入，或「让 agent 给建议」后逐条处理）、**同步范围**（两个预设、方向、插件清单和配置字段、范围 JSON 导入/导出）、**同步**（配对后出现：对方变更、冲突、按角色的「看差异」「发给对方」或「发布本机改动」）。
- **右列 · 连接与工具**：**连接**（网络选择、设备列表与撤销、邀请新设备、我去连别的设备，含邀请链接、地址、邀请码、SSH 隧道与「验证链接」；右上角可「重新打开指引」「重置同步」）、**更多**（离线快照、归档已处理提案、最近活动）。
- **底部**：**高级**折叠（自动应用、检查间隔、允许的改动类型、排除与只留本机规则、模型复核）。

所有文本输入框都有明显边框，聚焦时边框变蓝并出现外圈高亮。

首次打开且未配对时，面板会在两列上方显示连接指引：选「中心模式 / 去中心化（点对点）」「创建网络 / 接入现有网络」「局域网 / SSH 隧道 / 公网」，点「填好并继续」即把预设填进「连接」卡（创建 = 高亮对应按钮；接入 = 展开接入表单并选好对方类型），同时关掉指引。点「我自己来」直接关掉；关闭状态记在本机 localStorage，下次不再出现，可用「连接」卡右上的「重新打开指引」找回。配对选错时点「重置同步」并确认，即可回到未配对重新选；已勾选的同步范围保留，连接凭据会被删除。

资源目录只返回包名、插件的启用状态和配置条目 ID/字段路径，不返回配置值。插件清单在进入页面时自动读取；读取失败可在原处重试。

## 首次连接

未配对时先选网络，再选连接方式；也可以先用首次指引填好预设：

- **局域网**：用可信内网里的 `http://设备IP:3080`。明文 HTTP 现在允许，但邀请码是唯一凭据，只在可信网络使用，请勿在公网用 HTTP。
- **SSH 隧道**：用私钥登录远端主机，远端只监听 `127.0.0.1`，私钥本身即凭据。只需填写 SSH 主机、用户、私钥路径和 SSH 端口（默认 22）；远端 DSH 的 HTTP 端口固定 3080。
- **公网**：用 `https://域名:3080`，必须带邀请码。拿到邀请码的人就能接入，请私下传递。

1. **让别的设备连我**：把本机设为接受方。配对成功后可以生成邀请；页面会把「其他设备访问本机的地址」+ 邀请码拼成一条邀请链接（SSH 模式生成 `ssh://` 链接），复制后私下发给对方。邀请是一次性入口，24 小时过期，不要贴进公开 issue、截图或日志。
2. **我去连别的设备**：把对方发来的完整邀请链接粘到「邀请链接」，点「解析链接」自动填好地址与邀请码；点「验证链接」确认地址和 token 有效，**验证通过后「连接」按钮才可用**。也可以手工填写地址、邀请码并选择对方是中心还是点对点。
3. **两台设备直连**：本机建立点对点监听端，生成邀请交给对方；对方用邀请链接连过来。

配对成功后顶部显示角色与最近联系时间，「同步」卡出现，「暂停」可用。对方长时间没有联系时显示等待，而不是实时在线。设备被撤销后，重新连接需要新的邀请。

## 只同步插件

「只同步插件」只同步插件装没装、开没开，不传任何配置内容。

1. 打开设置，「同步范围」进入页面时自动读取本机插件清单。
2. 选中预设「只同步插件」。
3. 勾选要同步的插件。勾选、取消、全部勾选、全部不勾都会立即保存，没有保存按钮；保存失败会提示原因并回到服务器上的旧值。
4. 「建议」卡显示还有多少插件未纳入；「全部纳入」把它们一次性加进草稿并保存。也可以「让 agent 给建议」，再逐条「纳入」或「留本机」。

## 整个插件的设置

插件清单里带配置条目的插件会多一个「同步设置」勾选框。勾上以后，该插件的条目会加入 `include`、它的**全部非密钥字段**写入 `configFields`，同时开启 `caps.configSet`；取消勾选会把该条目从 `include` 和 `configFields` 一起移除，并关掉 `configSet`。密钥类字段不会出现在清单里，也不会被批量勾选。没有单独的「配置项」页面或逐字段勾选，范围 JSON 导入/导出仍包含这些配置条目。
5. 清单支持搜索。系统插件和同步器自身受保护，不会被同步计划修改。
6. 一个插件都不勾时页面会提示：保存后不会同步任何插件。这是白名单语义，不是“清空等于全部”。

方向只在需要单向时改：双向、只推送、只拉取。方向只决定传输方向，不代表允许某类写入；安装、升级和配置写入仍受能力开关与审批约束。

## 记忆（灵枢）同步

「同步范围」的插件清单下面是「记忆（灵枢）」块，按层显示本机可同步的节点数。

1. 先确认本机装的是灵枢（`@furongjun1999/dsh-memory`）。插件在 profile 的 `node_modules` 里找它的 Python 包；找不到时这一块只显示数量，勾选框不可用。
2. 勾选要同步的层。默认只提供 `contextual`（情景）、`goals`（目标）、`unresolved`（未解）；`knowledge`（知识）与 `structural`（结构）可以勾，但写入要过灵枢的分层复核闸。`self`、`anchor` 不在列表里。
3. 勾选即保存：写入 `include`（`lingshu:<层>`）、`policy.lingshu.layers`，并自动开启 `memoryWrite` 能力。取消全部层会关掉这个能力，也不再产生记忆计划。
4. 配对后在「同步」里会出现「记忆（灵枢）」计划卡。看差异、勾选、一次点击批准并应用。记忆写入永远不自动应用。
5. 结果里的 `memory-needs-review` 表示灵枢拒写：该层没有复核通道（默认 `enforce`）。这不是插件故障，也不是可以重试通过的失败；要么在灵枢侧补齐复核（`MDCG_REVIEW_CHANNELS` / 复核单元），要么不要同步这一层。

同步的内容是节点的规范化正文与语义字段。本机易变字段（访问计数、`last_access`、`importance*`、`session`、`writer`、`edges`、`protected` 等）不参与比较也不上送，覆写时保留本机值；`sensitivity` 由本机继承，远端不能把密级降级。密级高于策略上限（默认 `internal`）的节点、加密节点，以及命中灵枢 `data/policy.json` 禁写模式的节点不会外发。

写入由 `lib/lingshu-bridge.py` 调用灵枢库完成：它持有跨进程节点锁、维护索引，并在失败时如实返回。插件不会直接改 `.md` 文件。

## 配置的同步边界

- 配置只在插件清单里按「同步设置」整包勾选；没有逐字段选择界面，也不导出整个配置对象，只导出清单列出的非秘密字段。
- 看起来像秘密的字段不会列出，也不会被导出。键名/值的秘密识别只是额外防线，不是完整检测：即使键名没有 token/password，值也可能是秘密，所以请先确认该插件的配置适合共享。
- 本机应用会在 `configEditor` 的当前完整配置上叠加允许字段，保留本机秘密、未选字段及未声明删除的内容。远端发送的 `secretKeys` 不获得信任。配置条目必须活动、唯一可寻址且属于对应第三方 bundle；停用、重复 ID、被覆盖或不可寻址条目不会退回整文件写入。

## 勾选即生效

设置页没有“保存策略”按钮：插件勾选、同步设置、方向、自动应用和模型开关在改动后立即保存；排除/只留本机和模型名称在停止输入约 600 毫秒后保存。

- 保存时一律写 `default:'deny'`：勾了才同步，一个都不勾就不同步。`mode` 由自动应用决定，开启写 `managed`，关闭写 `selective`。
- 设置页下一次保存起，旧版的 `default:'allow'` 不再写入；在旧策略里清空 `include` 等于全同步的坑已消除。
- “排除同步”“本机专属”每行一个资源键，插件使用包名、配置使用 loader 条目 ID，末尾 `*` 可匹配前缀。保护顺序为系统/同步器保护 → 本机专属 → 明确纳入 → 排除 → 默认规则。对一个 bundle 设置本机专属，也会保护它所属的配置条目。
- 方向和写入能力不同：方向决定允许推送/拉取；具体安装、升级、启用、停用、写配置还要在「允许同步的改动」里逐项打开，默认只开启用/停用。
- 自动应用在「高级」里：开启后才显示检查间隔（60000–86400000 毫秒）。每轮只对当前策略允许的低风险启停/配置变更自动应用；安装、升级、冲突覆盖和高风险批次始终保留人工审批。

手动与选择性模式共用同一审批链；选择性模式没有另一个会隐式写入的调度器。

## 导入/导出范围

「同步范围」底部可以导入/导出范围 JSON：

- 导出在本地生成文件，只包含当前勾选的插件 key；没有勾选时不可导出。
- 导入在本地读取文件，只接受本页导出的格式；不在本机清单里的 key 会被丢弃，导入后同样立即保存。
- 文件只含插件范围，不含配置字段、方向、排除规则或能力开关；换设备后仍要核对配置字段和高级规则。

## 看差异、发布与应用

配对后「同步」卡按插件和配置分别显示计划，按钮按角色区分：

- 成员（设备，或已连上对端的点对点端）显示「看差异」和「发给对方」。
- 中心，或还没连上对端的点对点监听端显示「发布本机改动」。中心没有上游可拉，所以不会出现「看差异」「发给对方」。

成员的操作顺序：

1. 点「看差异」：拉取对方已发布的状态与本机比较，生成计划。检查一种资源不会清空另一种计划的批准。
2. 点「发给对方」：把本机改动作为提案发给对方；对方在「对方发来的变更」里「接受并发布」或「拒绝」，接受后才进入其期望状态。
3. 审批前可以比较资源键、操作、来源以及内容指纹。面板不展示配置值；需要核对正文时，使用自己熟悉的本机编辑器。
4. 勾选要应用的操作，然后一次点击「把这 N 项改到本机」：这一次点击会完成批准和应用，不需要再点第二个按钮。应用只在能拉取的成员侧可用；方向设为只推送时「看差异」也不出现。
5. 安装与升级默认不勾选，需逐项确认；高风险操作会标出。存在冲突时不能应用，先处理冲突。
6. 结果会区分已应用、需重启、失败、冲突和部分完成；「需重启」表示宿主已保存变更，当前运行代码还需要重启，不等同运行态已验证。

中心或点对点监听端改完本机资源后点「发布本机改动」：把当前范围内的插件/配置写成新的期望修订并推进 revision，对端下次「看差异」时拉取。

审批绑定计划内容、来源修订、本机基线和本机策略。来源修订、本机基线或策略变化会让旧计划失效，必须重新检查和批准。对未批准操作返回拒绝，不会“顺便”应用。

安装先以停用状态落地；只有启用也获批准并满足依赖时才启用。降级被单独阻止。成功单项会持久化去重；未成功单项可在基线仍匹配时重试。失败结果不等于系统已完整回滚；插件外部副作用无法通用撤销，配置更新走 DSH 编辑器。

## 冲突

两边都改了同一个资源时进入冲突。冲突只显示资源键和版本指纹，不显示配置值。

- 「保留本机」保留本机版本，不采用对方内容。
- 「采用对方」会生成新计划，必须重新批准后才写入。
- `ai-suggest` 只是待人工审查的占位，不会伪装成模型已经完成内容合并。
- 本机单方改动不会被当成远端更新自动覆盖；采用传入版本后也必须重新批准。

## 建议与模型复核

建议只扫插件：系统插件给「留本机」、已停用给「先不用」、设备专属插件（IM / 记忆 / 聊天类，账号、会话或状态绑定本机）给「留本机」且其设置也不纳入同步、其余普通插件给「纳入」；已经在 `include` 里的不再建议。记忆数据走独立的灵枢资源域（需显式纳入并过层/密级闸），`dsh-memory` 插件包本身仍按设备专属留本机。「让 agent 给建议」只产出建议，不改策略；「纳入」或「留本机」由用户点击后才写入 `include`/`localOnly`（同时清空待用批准），不需要再点保存。

可选模型仅接收插件元数据（key、enabled、kind），不会收到配置值或其他内容。它不能直接批准或调用写入；会产生供应商请求和费用。模型不可用或返回无效内容时保留启发式建议。0.3.0 没有对真实收费供应商调用作验收承诺。

## 离线快照

导出仅包含当前本机策略允许对外提供的已发布资源。设备希望导出自己的修改，应先按拓扑发布/提交；导出不是整个磁盘扫描备份。

粘贴快照 JSON 后按「导入」，插件和配置都会检查。未签名快照始终提示来源不可信；HMAC 要由本机已识别的共享密钥验证。快照有完整性/来源校验而没有加密，应按敏感文件保管。

导入只暂存候选状态，不能改本机策略、写资源或把导入内容升级为已同步基线。没有签名也不等于可以跳过字段/路径/资源类型校验。过期或恶意载荷即使重算普通摘要也不能绕过资源校验和本机批准。快照只包含插件与配置两类资源；灵枢记忆节点不进快照，也不能由快照导入。

## 撤销设备、审计与升级

「连接」里列出已配对设备。对方长时间没有联系会显示离线；撤销入口只在负责邀请的一侧出现。节点列表中“撤销设备访问权限”会拒绝该设备后续请求，撤销本机待用批准、相关待审提案/队列。不声称能删除对端已保存的副本或使对方失去已获知的内容。重新连接需要新的邀请。

私有状态存放在 `$DSH_HOME/plugin-sync/<profile 作用域摘要>/state.json`，权限 0600，目录 0700。摘要绑定 home、profile 名和目录；认证秘密通过 DSH credentials 按相同作用域独立存储。审计只保留最近 2000 条、序号随重启延续，不维护无界的重复 JSONL。每类已发布资源最多 512 条、待审提案最多 64 条、收到的提案历史最多 256 条、点对点待送提案最多 32 条；总状态限制 16 MiB。达到上限会明确拒绝新操作，不自动淘汰待审内容。「更多」里的“归档已处理提案”会先将已决提案及其冲突明细保存在同一私有状态目录的 `archives` 子目录，再移出活动历史释放容量；待审提案保留，归档或状态提交失败不会删原记录。界面显示归档件数与文件标识。资源或总状态仍超限时应先备份并缩小范围；不会用自动删待审数据来伪装持续可用。

从 0.2.0 升级：首次加载旧状态会自动迁移并落盘，删除旧通用记忆域的字段、`caps.memWrite` 和带 `adapterId/relativePath` 的旧建议；旧状态不会因多余字段校验失败。远端发来的旧 `kind:'memory'` 资源仍会被拒绝。从 0.3.x 升到 0.4.0 时状态会补上灵枢域的槽位与 `policy.lingshu`，默认不包含任何层。旧版 `default:'allow'` 的范围语义不再写入，但迁移不会静默改写旧策略；请到「同步范围」确认并触发一次保存（勾选或取消任意插件即可），保存前旧状态里的 `default` 仍按原值生效。状态与凭据路径不变，不需要重新配对。

0.1.0 开发版曾共享状态目录与凭据地址，0.2.0 不自动迁入旧共享状态；请在新作用域重新配对并重新选范围，避免把错误身份或旧秘密沿用到新节点。保留旧目录作人工检查，升级过程不会自动删除用户数据。

## 中心模式

中心可以管理多个设备。所有节点都装在普通 DSH profile 中。

1. 中心选择“让别的设备连我”，以本机现有资源建立初始期望状态。
2. 中心生成邀请；每个邀请只用于一次配对，24 小时到期。不要把邀请贴进公开 issue、截图或日志。
3. 设备选择“我去连别的设备”，输入 HTTPS 地址，或使用配置好的 SSH 连接，再输入邀请和本 profile 名称。
4. 中心在本机改完插件或配置后，点「同步」卡上的「发布本机改动」，把当前范围写成新的期望修订；设备下次「看差异」时拉取。
5. 设备在「同步」里按插件/配置分别「看差异」；本机改动通过「发给对方」提交提案。
6. 中心在「对方发来的变更」里查看来源和资源键，选择「接受并发布」或「拒绝」。已过时提案要重新对账后提交。
7. 中心接受只改变权威期望状态；成员仍需检查并满足本机策略/审批才会写入。

中心没有上游，不显示「看差异」和「发给对方」；这两类按钮只属于成员。暂停会拒绝新的远端配对、读取和提案，并阻止新的本机写入。正在进行的第三方包管理调用无法撤销；已完成的单项结果会持久化，后续操作停止。

## 点对点模式

本版本支持一对设备，复用相同资源、策略和审批机制。

- 第一端选择“两台设备直连”建立监听端，在「连接」里生成邀请（一次性、24 小时）。已有已连接对端时邀请按钮禁用，先撤销原设备。
- 第二端选择“我去连别的设备”，填写第一端地址和邀请，并把对方类型选为点对点。
- 监听端没有上游，用「发布本机改动」发布自己的范围；加入端用「看差异」拉取监听端状态，并用「发给对方」把本机改动作为提案提交。
- 提案由成员侧提交；对方接受后才发布新修订。尚未交换状态会显示等待，而不会伪装成已同步。
- 并发版本保留，提案冲突的选择只记录决定；真正接受提案时才发布新修订。

这不是多跳网状网络，也没有自动选主或信任传播。一个点对点节点需要换设备时，先撤销原设备访问；多台设备持续协作采用中心模式。

## 网络与 SSH

HTTPS 地址填写对端 DSH 服务的基础地址。非回环明文 HTTP 会被拒绝，URL 不能带用户名、密码、查询令牌或 fragment。请求不会跟随重定向转发凭据。

SSH 使用系统 `ssh`，直接转发到远端回环 HTTP 端口，不在远端运行 shell 或 curl。设置中只需填写 SSH 主机、用户、私钥绝对路径和 SSH 端口（默认 22）；远端 DSH 的 HTTP 端口固定 3080，无需填写。私钥保留本机文件中；同步状态只保存连接参数。两端都须安装本插件。

主机密钥由系统 OpenSSH 按标准 TOFU 流程管理：使用 `StrictHostKeyChecking=accept-new`，首次连接自动把指纹写入系统默认的 `~/.ssh/known_hosts`，之后同一主机指纹变化即拒绝连接。不提供关闭校验的「快捷模式」。此模式要求 SSH 服务允许 TCP forwarding。真实 SSH 验证覆盖同机隔离 sshd，跨主机防火墙、跳板机、代理和网络策略需另行确认。
