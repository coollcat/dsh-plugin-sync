# 使用说明

## 确认安装在正确实例

节点是 DSH profile，而不是整台电脑。在插件管理中确认“设备同步”已安装并启用，再打开“设置 → 设备同步设置”。如果只有另一套测试实例中出现入口，当前实例仍需要安装。安装器返回 `applied`、`restart-required`、失败等状态时，按实际结果处理；不要用包目录存在来判断界面已经加载。

Web 和桌面都使用 README 的同一 GitHub 来源。更换 profile 名即可，不需要为桌面另做安装包。此版本的真实宿主验收基于 Linux 的 DSH 0.2.2-rc.3；其他宿主版本按 manifest 的兼容范围检查，并以安装结果为准。

## 本机策略与可选资源

在设置面板先查看本机可选资源。资源目录只返回包名、配置条目 ID/字段路径和记忆相对路径，不返回配置值或文件正文。勾选只改变表单草稿；点“保存策略”才生效。

“纳入同步”“排除同步”“本机专属”每行一个资源键。插件使用包名；配置使用实际 loader 条目 ID；记忆使用 `adapterId:相对路径`，例如 `memory:notes.md`。末尾 `*` 可匹配前缀。

保护顺序为系统/同步器保护 → 本机专属 → 明确纳入 → 排除 → 默认规则。配置和记忆仍要求明确纳入；配置还需要字段白名单。对一个 bundle 设置本机专属，也会保护它所属的配置条目。

同步方向决定允许推送、拉取或两者。方向和写入能力不同：允许拉取并不等于允许写入，允许推送也不会自动发布全网修订。

- **手动同步**：用户按按钮检查和应用。
- **选择性同步**：保存明确范围，仍由用户检查、批准和应用。
- **完全托管**：必须另外开启“自动对账”；每轮只对当前策略允许的低风险启停/配置变更自动应用。

手动与选择性模式共用同一审批链；选择性模式没有另一个会隐式写入的调度器。自动对账间隔范围为 60000–86400000 毫秒。安装、升级、记忆写入、冲突覆盖与高风险批次始终保留人工审批。

## 配置字段的选择

未知插件的配置不能靠字段名就保证无秘密，所以默认不导出。先明确选择配置条目，再勾选可以分享的字段。高级 JSON 格式：

```json
{
  "example-entry": [
    ["appearance", "theme"],
    ["network", "timeoutMs"],
    ["literal.key"]
  ]
}
```

路径由键段数组组成。`["literal.key"]` 表示一个带点号的键，不会被拆成两级路径。不要选择包含账户、私密文本或凭据的整个对象；即使键名没有 token/password，也可能是秘密。

本机应用会在 `configEditor` 的当前完整配置上叠加允许字段，保留本机秘密、未选字段及未声明删除的内容。远端发送的 `secretKeys` 不获得信任。配置条目必须活动、唯一可寻址且属于对应第三方 bundle；停用、重复 ID、被覆盖或不可寻址条目不会退回整文件写入。

## 中心模式

中心可以管理多个设备。所有节点都装在普通 DSH profile 中。

1. 中心选择“建立中心”，决定从空状态开始，或从已纳入范围的本机资源开始。
2. 中心生成邀请；每个邀请只用于一次配对，24 小时到期。不要把邀请贴进公开 issue、截图或日志。
3. 设备选择“加入中心”，输入 HTTPS 地址，或使用配置好的 SSH 连接，再输入邀请和本 profile 名称。
4. 中心修改本机资源后，点“发布纳入同步范围的本机资源”。设备在对应三类计划区域检查差异。
5. 设备本机改变后，可按类别提交提案。中心查看来源/资源键，选择“接受并发布”或“拒绝提案”。已过时提案要重新对账后提交。
6. 中心接受只改变权威期望状态。中心本机或其他设备仍需检查并满足本机策略/审批才会写入。

暂停会拒绝新的远端配对、读取和提案，并阻止新的本机写入。正在进行的第三方包管理调用无法撤销；已完成的单项结果会持久化，后续操作停止。

## 点对点模式

本版本支持一对设备，复用相同资源、策略和审批机制。

- 第一端选择“建立点对点邀请端”，再生成邀请。
- 第二端选择“连接点对点设备”，输入第一端地址和邀请。
- 两端各自发布自己的共享状态。加入端检查时交换双方状态，监听端可据已收到的状态检查差异。
- 监听端提交的提案先排队，由加入端下次检查时领取和确认。尚未交换状态会显示等待，而不会伪装成已同步。
- 并发版本保留，提案冲突的选择只记录决定；真正接受提案时才发布新修订。

这不是多跳网状网络，也没有自动选主或信任传播。一个点对点节点需要换设备时，先撤销原设备访问；多台设备持续协作采用中心模式。

## 网络与 SSH

HTTPS 地址填写对端 DSH 服务的基础地址。非回环明文 HTTP 会被拒绝，URL 不能带用户名、密码、查询令牌或 fragment。请求不会跟随重定向转发凭据。

SSH 使用系统 `ssh`，直接转发到远端回环 HTTP 端口，不在远端运行 shell 或 curl。设置中填写 SSH 主机、用户、私钥绝对路径、`known_hosts` 绝对路径，以及远端 DSH 的 HTTP 端口。私钥保留本机文件中；同步状态只保存连接参数。两端都须安装本插件。

首次使用前，通过自己的可信渠道核实主机指纹并准备 `known_hosts`；未知/变化的 host key 必须失败，不能关闭校验绕过。此模式要求 SSH 服务允许 TCP forwarding。真实 SSH 验证覆盖同机隔离 sshd，跨主机防火墙、跳板机、代理和网络策略需另行确认。

## 计划、冲突与失败

插件、配置、记忆分别保存计划、批准和结果。检查一种资源不会清空另一种计划的批准。对未批准操作返回拒绝，不会“顺便”应用。

审批前可以比较资源键、操作、来源以及内容指纹。面板不展示配置值或记忆全文；需要核对正文时，使用自己熟悉的本机编辑器。采用传入冲突版本后会生成新计划，必须重新批准；保留本机会保留本机差异。`ai-suggest` 只是待人工审查，不能伪装成模型已经完成内容合并。

本机单方改动不会被当成远端更新自动覆盖。来源修订、本机基线或策略变化会让旧计划失效。安装先以停用状态落地；只有启用也获批准并满足依赖时才启用。降级被单独阻止。

成功单项会持久化去重；未成功单项可在基线仍匹配时重试。失败结果不等于系统已完整回滚。插件外部副作用无法通用撤销，配置更新走 DSH 编辑器，记忆写入有本地备份。

“需重启”表示宿主已保存变更，当前运行代码还需要重启；不等同运行态已验证。主面板显示最近请求结果和最近联系时间，不把已配对一概显示为实时在线。

## 记忆与建议

适配器映射到本机 `$DSH_HOME` 下的 `.dsh-memory`、`persona`、`soul`。文件类型由本机适配器限定；无远端自选根目录、脚本执行或删除入口。单文件上限 256 KiB，网络载荷上限 512 KiB；过大集合会拒绝而不是悄悄截断成成功同步。

人格/规则内容可能含机器与身份信息，默认启发式会倾向本机专属。扫描建议本身不会写记忆；采用只修改本机范围策略，还需保存的能力/计划/批准才能写内容。

可选模型仅接收已纳入范围资源的元数据。它不能直接批准或调用写入；会产生供应商请求和费用。模型不可用时保留启发式建议。没有对真实收费供应商调用作本版验收承诺。

逐文件 `.owner` 阻止另一个 profile 读取/导出或覆盖同一路径；未标 owner 的既有文件允许作为本机初始候选，但默认仍不外发，必须明确选入。首次同步写入会记录 owner。短期 `.sync-lock` 阻止并发写入。不要把备份、owner、锁文件再纳入同步。进程异常留下锁时先确认没有写入者，再人工处置；不提供会删除活跃锁的“自动修复”。

## 离线快照

导出仅包含当前本机策略允许对外提供的已发布资源。设备希望导出自己的修改，应先按拓扑发布/提交；导出不是整个磁盘扫描备份。

粘贴快照 JSON 后按“导入并检查差异”，三个域都会检查。未签名快照始终提示来源不可信；HMAC 要由本机已识别的共享密钥验证。快照有完整性/来源校验而没有加密，应按敏感文件保管。

导入只暂存候选状态，不能改本机策略、写资源或把导入内容升级为已同步基线。没有签名也不等于可以跳过字段/路径/资源类型校验。过期或恶意载荷即使重算普通摘要也不能绕过资源校验和本机批准。

## 撤权、审计与升级

节点列表中“撤销设备访问权限”会拒绝该设备后续请求，撤销本机待用批准、相关待审提案/队列。不声称能删除对端已保存的副本或使对方失去已获知的内容。重新连接需要新的邀请。

私有状态存放在 `$DSH_HOME/plugin-sync/<profile 作用域摘要>/state.json`，权限 0600，目录 0700。摘要绑定 home、profile 名和目录；认证秘密通过 DSH credentials 按相同作用域独立存储。审计只保留最近 2000 条、序号随重启延续，不维护无界的重复 JSONL。每类已发布资源最多 512 条、待审提案最多 64 条、收到的提案历史最多 256 条、点对点待送提案最多 32 条；总状态限制 16 MiB。达到上限会明确拒绝新操作，不自动淘汰待审内容。提案区可点“归档已处理提案”：先将已决提案及其冲突明细保存在同一私有状态目录的 `archives` 子目录，再移出活动历史释放容量；待审提案保留，归档或状态提交失败不会删原记录。界面显示归档件数与文件标识。资源或总状态仍超限时应先备份并缩小范围；不会用自动删待审数据来伪装持续可用。

0.1.0 开发版曾共享状态目录与凭据地址，0.2.0 不自动迁入旧共享状态；请在新作用域重新配对并重新选范围，避免把错误身份或旧秘密沿用到新节点。保留旧目录作人工检查，升级过程不会自动删除用户数据。
