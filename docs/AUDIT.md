# 0.2.0 安全与业务流程审计

审计日期：2026-11-19。对象为此仓库的插件源码和实际打包内容；宿主依据 DSH 0.2.2-rc.3 随包文档、类型与实现核对。本记录不会把隔离实例验收当成使用者当前 profile 已安装的证据。

## 发现与修复

早期 47 个单测通过并不能证明完整流程正确。本轮重新追踪入口、策略、计划、批准和实际写入，确认并修复了以下问题。

### 安全边界

- 原状态目录和 credentials 固定地址被所有 profile 共用。现按 home/profile/目录生成独立作用域；损坏状态拒绝启动，禁止静默重置。
- 原配置只按键名脱敏，未知 schema 可把秘密放在普通字段中。现配置默认不外发，必须明确纳入资源并列出非秘密字段路径；入站/出站均重新投影。
- 原 `localOnly`/方向主要作用在计划上，不能覆盖提案、初始发布与快照外发。现全部外发入口复用相同本机范围，配置按真实所属 bundle 保护。
- 原内存适配器只校验数据目标，未保护 owner sidecar；还可能跟随根目录别名、读取其他 profile 已拥有的文件。现验证根/父路径/sidecar，拒绝符号链接和硬链接别名，按 owner 过滤读取与写入，并限制扩展名、创建基线与大小。
- 原快照仅验证整体摘要与数组类型，重算普通摘要可夹带无效资源。现复用在线资源类型、地址、实际内容哈希与大小校验，明确区分未可信来源和本机密钥验证的 HMAC。
- 原 SSH 远端 curl 只有路径而没有完整地址；shell 展开后 bearer 还可能出现在远端 curl argv。现使用系统 `ssh -W` 直接 TCP forwarding，生成完整 HTTP 请求，不启动远端 shell/curl；严格校验 host key，超时终止子进程，限制响应字节。
- 原暂停未覆盖对端读取/提案；没有撤权入口。现暂停阻断新同步入口，撤权拒绝后续认证并清除待用批准/队列。
- 原 agent 检查可能返回正文或建议片段。现在工具返回元数据投影；用户界面的配置值/记忆内容也不混入计划显示。

### 流程正确性

- 修正 `check(all)` 漏掉插件和配置，以及 UI 导入快照把对象误传给字符串解析器的问题。
- 三类计划分开管理批准；策略、来源或本机基线改变会失效旧批准，部分批准不能绕过安装依赖启用插件。
- 安装先停用落地；升级保持真实启用状态。成功单项先持久化，失败可以在正确基线下重试，升级失败后的启用重试不再误判基线。
- 配置写入核实唯一活动条目与真实 bundle 归属，锁内以当前完整配置为基底；不能写错相同 ID 的条目或覆盖本机秘密/非受控字段。
- 对等角色此前只在直接函数测试里“可用”。现在真实角色可交换状态、排队/领取/确认提案；冲突决定到接受时才发布，过时提案需要重新检查。加测还复现并修复了监听端反向提案“已接受但无本机应用计划”的断路：目标选择按因果关系合并本机已接受状态和对端状态，保留无关资源；单测验证下一轮不回滚，真实 HTTP 验证接受后能批准并落盘，无需额外发布绕路。
- 单方本机改动保留为差异；并发改动进入冲突，人工选择生成新计划再批准。`ai-suggest` 不再伪装成模型选择中心版本。
- 设置页补齐三域能力、方向、范围和字段选择、按需本机资源目录；加载失败可就地重试。提案、计划、设置、快照失败都不再显示假成功。
- 审计、资源和队列均有上限。已决提案可通过本机私有备份后归档释放队列；不会删除待审内容，也不会把满队列伪装成成功。

### 冗余与可维护性

- 合并三类资源计划器和共用策略/校验路径，减少各域分支漂移。
- 合并审计实现，修复滚动窗口后序号重复；移除第二份无界 JSONL 副本写入。
- 清除未接线的帮助代码和 locale 中重复的 UI 字典，保留 DSH 导出的显示元数据。
- 运行包仅提交原生 JavaScript；React 由宿主提供，测试 renderer 只作为开发依赖。新增字段、入口和发布白名单均有检查。

## 验证方法

自动回归覆盖真实 React hooks/事件参数、宿主 HTTP harness、状态/凭据隔离、协议输入、跨 profile owner、配置 allowlist、并发基线/批准、单项重试、双向点对点队列、归档失败不删、容量拒绝、快照伪造、HTTP/SSH 限制。

真实 SSH 验收使用独立高端口 sshd、临时公钥和 `known_hosts`，覆盖公钥连接、中文 HTTP 字节长度、chunked 响应、HTTP 503、坏 JSON、未知 host key 拒绝，以及无 bearer argv/无远程 shell。

真实 DSH 验收要求两套全新 DSH_HOME、从 Web 模板创建 profile，以最终 tarball 安装插件；检查实际配置组装、客户端 bundle、设置/插件入口，执行配对→发布→三域差异→逐项批准→应用并核对结果。安装副本和源代码逐文件哈希必须一致。

公开发布检查扫描当前源码和新建 Git 历史，不将测试实例、凭据、截图中的真实账户、缓存或本机绝对路径带入分发包。仓库根包含 manifest、宿主/客户端入口、patch、locale、icon 和文档；无依赖作者机器目录的安装步骤。

## 适用边界

点对点支持一对设备，多设备使用中心；不存在已验证的多跳网状同步。自动应用不覆盖记忆或软件安装。没有真实收费模型调用、两台物理主机 WAN、防火墙/代理组合、Windows/macOS 桌面端的全矩阵验证。

本机同账户任意改代码的攻击者不在进程内隔离保证内。字段启发式不是完整秘密检测，用户明确选入的普通字段仍需自己确认可分享。没有全局回滚、撤销外部副作用或远程抹除已获副本的保证。
